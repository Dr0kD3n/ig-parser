# Логика работы страницы настроек (SettingsTab)

Эта страница является центром управления конфигурацией бота, аккаунтами и целевыми аудиториями.

## 1. Навигация и общие настройки
- **Переключение вкладок**: Состояние `settingsTab` управляет отображением подразделов (Аккаунты, Имена, Города, Ниши, Доноры). Выбор сохраняется в `localStorage` (`ig_settings_tab`).
- **Глобальные флаги**:
  - `humanEmulation**: Включает имитацию действий человека для снижения риска блокировок.
  - `showBrowser**: Определяет, будет ли отображаться окно браузера при работе бота.
  - `concurrentProfiles**: Количество одновременно работающих профилей (от 1 до 20).
- **Обновления**: При загрузке выполняется запрос к `/api/update/check`. Если доступна новая версия, появляется кнопка установки, которая вызывает `/api/update/install`.

## 2. Управление аккаунтами (Вкладка "Аккаунты")
### Основные функции:
- **Добавление аккаунта**: Принимает имя, прокси и куки. Создает уникальный ID на основе текущего времени.
- **Удаление**: Полностью удаляет аккаунт из списка и всех активных задач.
- **Редактирование (`handleSaveEdit`)**:
  - Позволяет менять имя, прокси, User-Agent и Fingerprint (системные данные).
  - **Регенерация системных данных**: Функция обновления Fingerprint через API для "омоложения" профиля.
- **Интерактивные действия**:
  - **Авторизация (`handleLogin`)**: Запуск процесса входа в Instagram.
  - **Браузер (`handleOpenBrowser`)**: Открывает управляемое окно браузера. Параметр `forceRestore` позволяет загрузить профиль с принудительной очисткой/восстановлением (например, для прогрузки фото).
  - **Прогрев (`handleWarmup`)**: Запуск автоматизированного сценария "прогрева" аккаунта для повышения доверия системы (ходьба по сайтам, имитация активности).

## 3. Распределение задач (Drag & Drop)
Аккаунты распределяются по 4 основным ролям:
1. **Parser (Поиск)**: Аккаунты для поиска целевой аудитории.
2. **Scraper (Сбор)**: Профили для детального сбора данных о найденных пользователях.
3. **Sender (Рассылка)**: Аккаунты, которые непосредственно отправляют сообщения.
4. **Profiles (Профили)**: Технические аккаунты для работы с профилями доноров.
- **Логика**: Аккаунты можно перетаскивать (Drag & Drop) внутри каждой секции для изменения приоритета их использования.

## 5. Управление донорами (Вкладка "Доноры")
Это самый сложный модуль, разделенный на две части:
### Общий список (Raw List):
- **Визуальный слой**: Отображает список доноров с подсветкой уже "отработанных" ссылок (зачеркнутая линия) и метаданными (ниша, город).
- **Слой ввода**: Позволяет вставлять ссылки списком. При вводе бот пытается сопоставить введенную строку с уже существующими объектами доноров для сохранения их метаданных.

### Группы доноров:
- **Создание групп**: Позволяет сегментировать доноров. Каждой группе можно назначить свои шаблоны сообщений.
- **DonorGroupCard**:
  - **Выбор доноров**: Интерфейс для быстрого добавления/удаления отсканированных доноров в группу.
  - **Шаблоны сообщений**: Многострочное поле для ввода текстов рассылки. Каждая строка — отдельный вариант сообщения (рандомизация при отправке).
- **Специальная группа "Все"**: Группа по умолчанию для всех доноров, не попавших в специфические сегменты.

# Логика работы страницы управления (ControlsTab)

Эта страница предназначена для оперативного контроля работы бота, мониторинга логов и визуального наблюдения за процессом.

## 1. Секция "Сборщик" (Scraper)
- **Назначение**: Управляет процессом глубокого сбора данных о целевой аудитории из профилей доноров.
- **Статус**: Точка рядом с заголовком горит зеленым, когда сборщик активен.
- **Функции**:
  - `Запустить/Остановить`: Основные команды управления процессом.
  - `Пропустить донора`: Позволяет принудительно завершить обработку текущего донора и перейти к следующему в списке. Полезно, если донор кажется нерелевантным или аккаунту трудно собрать с него данные.

## 2. Секция "Поисковик" (Parser)
- **Назначение**: Управляет процессом первичного поиска новых потенциальных клиентов по заданным в настройках параметрам.
- **Статус**: Индикатор активности (зеленая точка).
- **Функции**:
  - `Запустить/Остановить`: Управление жизненным циклом парсера.

## 3. Живой лог (Logs)
- **Группировка**: Логи автоматически группируются по сессиям и источникам (например, PARSER, SENDER, SCRAPER) для удобства чтения.
- **Интерактивность**:
  - Каждую группу логов можно свернуть/развернуть.
  - Кнопка `Очистить` удаляет историю логов из текущего вида.
  - Автоматическая прокрутка: Интерфейс всегда держит последние записи в поле зрения.
- **Live-индикатор**: Показывает, что системные сообщения поступают в режиме реального времени.

## 4. Прямая трансляция (Live View)
- **Принцип работы**: Отображает скриншот активного окна браузера, обновляемый каждые 2 секунды.
- **Особенности**:
  - Если бот не запущен или браузер закрыт, отображается заглушка "Браузер не запущен".
  - **Масштабирование**: При клике на окно трансляции открывается полноэкранный режим для детального изучения происходящего в браузере.
- **Статус**: Отображает активность браузера даже если основные процессы (сборщик/парсер) находятся в режиме ожидания.

## 5. Состояние интерфейса
- Все секции (Сборщик, Поисковик, Логи, Трансляция) поддерживают сворачивание.
- Состояние (развернуто/свернуто) сохраняется в браузере пользователя, чтобы при перезагрузке страницы интерфейс выглядел так же, как его оставил пользователь.

# Логика работы страницы профилей (ProfilesTab)

Эта страница — основное рабочее пространство пользователя для фильтрации, оценки и взаимодействия с собранной аудиторией.

## 1. Панель инструментов (Фильтры и поиск)
- **Поиск**: Позволяет мгновенно найти профиль по имени или никнейму.
- **Статус-фильтр**:
  - `Без статуса`: Новые, необработанные профили.
  - `Активные`: Все, кроме скрытых (дизлайкнутых).
  - `Лайк (без сообщения)`: Те, кто понравился, но кому еще не написали.
  - `Рассылка отправлена`: Список тех, с кем уже начат диалог.
- **Фильтр по Telegram**: Отбор профилей, у которых в био найдены и подтверждены контакты Telegram.
- **Фильтр по донору**: Позволяет посмотреть аудиторию, пришедшую от конкретного инстаграм-аккаунта.
- **Опции отображения**:
  - `Скрыть без фото`: Убирает профили, где боту не удалось загрузить аватар.
  - `Только город`: Фильтрация по совпадению с целевым городом из настроек.

## 2. Логика карточки профиля
Каждая карточка — это мини-панель управления конкретным пользователем:

### Визуальные индикаторы (Бейджи):
- 🎯 **Match Score (%)**: Интеллектуальная оценка релевантности профиля на основе его био и статистики.
- **Статус-теги**: Цветные метки "Просмотрено", "Лайк", "Скип", "DM Отправлено", "TG Найден".

### Умная обработка данных (Smart Bio):
- Бот автоматически очищает текст описания профиля от мусора, дублей и технических символов Instagram.
- Если в базе нет жестких цифр статистики, система пытается "вытащить" количество подписчиков прямо из текста био.

### Интерактивные зоны:
- **Центральные кнопки (при наведении)**:
  - `Instagram`: Переход в профиль.
  - `Telegram`: Если статус не подтвержден, бот откроет ссылку и параллельно запустит проверку существования аккаунта в TG.
- **Угловые кнопки управления**:
  - 💾 **Сохранить как донора**: Превращает текущий профиль в источник для нового сбора (рекурсивный поиск).
  - 🗑️ **Удалить**: Безвозвратное удаление профиля из базы данных.
- **Информация о доноре**: При наведении на имя донора всплывает окно с его краткой сводкой (фото, подписчики, био), чтобы понимать контекст происхождения лида.

## 3. Действия и голосование
- ❤️ **Лайк / ❌ Дизлайк**: Быстрая сортировка. Дизлайк скрывает профиль при стандартных фильтрах.
- ✈️ **Тег Telegram**: Ручная или автоматическая пометка наличия альтернативного канала связи.
- 🔵 **Написать сообщение**: Открывает модальное окно (или интерфейс) для отправки персонализированного сообщения через выбранные аккаунты-сендеры.

## 4. Технические особенности
- **Пагинация**: Профили загружаются порциями по 60 штук для обеспечения плавности интерфейса.
- **Проксирование изображений**: Фотографии загружаются через специальные прокси-сервисы (`weserv.nl` или внутренний `/api/proxy-image`) для обхода прямых блокировок Instagram и сохранения анонимности.

# Системная логика и архитектура приложения (App Engine)

Этот раздел описывает фоновые процессы и механизмы, связывающие интерфейс с сервером.

## 1. Механизм авторизации и безопасности
- **Bearer Authentication**: Каждое обращение к API (через `authFetch`) автоматически включает заголовок `Authorization`.
- **401 Interceptor**: Если сервер отклоняет токен (сессия истекла), приложение мгновенно сбрасывает локальное состояние пользователя и перенаправляет его на страницу логина (`AuthPage`).

## 2. Глобальное управление данными
### Интеллектуальное сохранение настроек (Debounce Save):
- Реализован механизм отложенного сохранения. После любого изменения в конфигурации (названия, лимиты, аккаунты), приложение ждет 1 секунду "тишины" перед отправкой данных на сервер. Это предотвращает лишние запросы при быстром вводе текста.
- **Индикатор прогресса**: В шапке отображается статус "Saving..." или "Saved", давая пользователю визуальное подтверждение фиксации данных.

### Мониторинг статистики:
- В заголовке приложения агрегируются данные в реальном времени:
  - Количество новых (неоткрытых) профилей.
  - Общее число просмотренных.
  - Успешно отправленные сообщения (акцентным цветом).
  - Сформированный пул лайков (зеленым цветом).

## 3. Диспетчер рассылки (DM Dispatcher Logic)
При клике на кнопку "На написать сообщение", система выбирает текст по следующему приоритету:
1. **Групповой шаблон**: Поиск группы, к которой привязан донор данного профиля. Если группа найдена и в ней есть сообщения — выбирается случайное из них.
2. **Группа "Все"**: Если персональной группы нет, проверяются шаблоны в спец-группе "Все" в настройках доноров.
- **Рандомизация**: Если в выбранном источнике несколько строк, выбирается случайная для защиты от фильтров спама.

## 4. Фоновые инструменты и SSE
### Поток системных логов (SSE):
- Используется технология `Server-Sent Events`. При входе в систему открывается постоянное соединение с сервером, который "проталкивает" новые записи логов сразу в терминал управления без лишних запросов от клиента.

### Восстановление медиа-данных (Photo Restore Engine):
- **Логика**: Позволяет массово перекачать аватарки, которые перестали отображаться (из-за блокировок или таймаутов).
- **Многопоточность**: Процесс идет параллельно (количество потоков равно `concurrentProfiles`).
- **Мониторинг**: Фронтенд опрашивает статус процесса каждые 3 секунды, отображая прогресс в реальном времени прямо на кнопке "Восстановить фото".

## 5. Модуль массовой рассылки (Mass Messenger Engine)
Этот модуль отвечает за автоматизацию отправки сообщений в промышленном масштабе с защитой от блокировок.

### Многопоточность и Чанки (Chunks):
- **Логика потоков (`concurrentProfiles`)**: Настройка определяет, сколько браузерных вкладок (потоков) бот открывает **одновременно**. Например, при значении `5`, бот берет 5 профилей и запускает 5 параллельных процессов отправки.
- **Цикл обработки**: Бот работает порциями (чанками). После завершения отправки во всех активных потоках текущего чанка, бот делает паузу и переходит к следующей пятерке.
- **Распределение аккаунтов**: Если назначено несколько аккаунтов-сендеров, бот распределяет их по потокам. Если аккаунт один, все 5 потоков будут работать от его имени (что повышает скорость, но требует осторожности с лимитами).
- **Имитация человека**: При включении `humanEmulation`, между чанками вставляется значительная случайная пауза (в среднем 15-35 секунд) для маскировки автоматизации под действия реального пользователя.

### Проверка истории:
- Перед отправкой бот заходит в чат и анализирует наличие переписки для предотвращения дублей.
- **Структурный анализ (DOM)**: Система ищет специфические контейнеры сообщений (`role="group"`, `.x13dflua`, `.x13a6bvl`). Наличие любого текстового пузырька (`role="none"`), не входящего в черный список системных надписей, считается признаком истории.
- **Контентная фильтрация**: Бот игнорирует служебные элементы (кнопки "Follow", статусы "Active now", "View profile") и сверяет текст с текущими шаблонами рассылки (например, "Вайб", "творческая", "взгляд").
- **Детекция исходящих**: Направление сообщения определяется по CSS-свойствам: цвет фона пузырька (синий/градиент) и выравнивание (`align-self: flex-end`). Если найдено хотя бы одно исходящее сообщение — профиль гарантированно пропускается.
- **Универсальность и контроль**: Логика адаптирована для работы как в полноэкранном Direct, так и в модальных окнах. В консоль выводится превью найденного текста для верификации причин пропуска.

## 6. Сбор обратной связи (Feedback Checker)
Модуль для автоматического анализа эффективности рассылки и сбора ответов.

- **Источник данных**: Бот открывает страницу `https://www.instagram.com/direct/inbox/` с первого доступного аккаунта-сендера.
- **Алгоритм поиска**: Система сканирует список чатов в Инбоксе, прокручивая его вниз. 
- **Сопоставление по именам**: Бот ищет совпадения **строго по полному имени** (Display Name), которое было зафиксировано в базе данных в момент отправки сообщения. Это обеспечивает максимальную скорость и точность в мультиязычном интерфейсе Instagram.
- **Детекция реакций**:
  - **Ответ (Replied)**: Обнаруживается по наличию синего индикатора (blue dot) непрочитанного сообщения в списке чатов.
  - **Лайк (Liked)**: Распознается по системному тексту "Liked a message" или "Отметил(а) «нравится»" в превью чата.
- **Оптимизация**: Бот автоматически прекращает сканирование, если нашел всех адресатов из истории или достиг конца списка чатов.

## 7. Мультиязычность и Локализация
- Система полностью поддерживает RU/EN интерфейс.
- Все текстовые ключи вынесены в `i18n.js`. Переключение языка мгновенно меняет весь UI без перезагрузки страницы, сохраняя текущий выбор в `localStorage`.
